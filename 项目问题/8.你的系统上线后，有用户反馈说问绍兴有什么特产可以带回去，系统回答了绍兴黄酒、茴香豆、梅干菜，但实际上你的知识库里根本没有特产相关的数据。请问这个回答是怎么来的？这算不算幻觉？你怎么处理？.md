

## 🧑‍💼 面试官点评：

---

### ✅ 答对的部分

- **"可能是降级到 Web Search 的结果"** — 如果你确实做了这个逻辑，那说得通
- **"AI 自检判断结果是否合理"** — 有校验意识

---

### ❌ 但有一个判断是错的

> **"我觉得不算幻觉"— 这个判断有问题！**

```
面试官听到这句话会直接追问：

"如果不是你的降级逻辑呢？"
"你怎么确定这个回答一定来自 Web Search？"
"如果这三个特产就是 LLM 自己编的呢？"
"你的系统能区分'来自知识库'和'来自LLM自身知识'吗？"
```

**这个问题的关键是：你的系统有没有能力分辨回答的来源？**

---

### 🎯 满分回答：

> **这个问题要分两种情况讨论：**
>
> ---
>
> **情况一：我的降级逻辑生效了，走了 Web Search**
>
> ```
> RAG 检索 → 没找到特产相关文档 → 置信度低于阈值
>   → 触发降级 → Web Search 搜索"绍兴特产"
>   → 拿到搜索结果 → LLM 基于搜索结果回答
>   → "绍兴黄酒、茴香豆、梅干菜"
> ```
>
> 如果是这种情况，回答有据可查，**不算幻觉**。
> 但需要告知用户信息来源不是本地知识库：
>
> ```
> "绍兴特产包括绍兴黄酒、茴香豆、梅干菜等。
>  ⚠️ 该信息来源于网络搜索，非本地知识库收录内容。"
> ```
>
> ---
>
> **情况二：降级逻辑没生效，LLM 用自身知识回答了**
>
> ```
> RAG 检索 → 没找到，但置信度判断不够严格
>   → 没有触发降级
>   → LLM 看到检索结果不相关，但自己知道绍兴特产
>   → 直接用训练时学到的知识回答了
>   → 绕过了 RAG 的约束
> ```
>
> **这种情况就是幻觉！**
>
> 虽然"绍兴黄酒、茴香豆"碰巧是对的，但问题在于：
>
> ```
> 这次碰巧对了 ≠ 每次都对
> 
> 下次用户问"绍兴有什么特色糕点"
> LLM 可能回答"桂花糕、龙井酥、松花饼"
> 其中"松花饼"可能根本不存在
> 用户信以为真，跑去找，找不到
> → 这就是幻觉的危害
> ```
>
> **关键认知：幻觉不是指"回答错了"，而是指"没有依据就回答了"。即使答对了，没有来源也算幻觉。**
>
> ---
>
> **怎么从机制上杜绝这个问题？三道防线：**
>
> **第一道：Prompt 严格约束**
>
> ```python
> system_prompt = """
> 【最高优先级规则】
> 1. 你只能基于参考资料回答
> 2. 如果参考资料中没有相关信息，
>    你必须回答"知识库暂无相关信息"
> 3. 绝对不允许使用你自己的训练知识来回答
> 4. 即使你知道答案，没有参考资料也不能回答
> """
> ```
>
> **第二道：回答必须标注来源**
>
> ```json
> {
>   "answer": "绍兴黄酒、茴香豆、梅干菜",
>   "sources": ["web_search: 绍兴特产推荐"],
>   "source_type": "web_search",
>   "from_knowledge_base": false
> }
> ```
>
> ```
> 前端根据 source_type 展示不同标签：
> 
> source_type = "knowledge_base"
>   → 显示 ✅ 来源：官方资料
> 
> source_type = "web_search"
>   → 显示 ⚠️ 来源：网络搜索（仅供参考）
> 
> source_type = "unknown" 或无 sources
>   → 显示 ❌ 该回答未经知识库验证
> ```
>
> **第三道：检索为空时的标准化处理流程**
>
> ```
> RAG 检索 → 置信度 < 阈值
>     ↓
> 是否开启 Web Search 降级？
>   ├── 是 → Web Search → 标注来源为"网络搜索"
>   └── 否 → 直接回复"知识库暂无相关信息，
>             建议补充以下内容：绍兴特产"
>                ↓
>         记录到"知识库缺失日志"
>         定期分析哪些问题被频繁问到但知识库没有
>         针对性补充数据
> ```
>
> **第三道防线里的"缺失日志"特别重要：**
>
> ```python
> # 知识库缺口记录
> def log_knowledge_gap(question: str, intent: str):
>     """记录知识库没覆盖到的问题"""
>     db.execute("""
>         INSERT INTO knowledge_gaps 
>         (question, intent, count, first_seen)
>         VALUES (:q, :intent, 1, NOW())
>         ON CONFLICT (question) 
>         DO UPDATE SET count = knowledge_gaps.count + 1
>     """, {"q": question, "intent": intent})
> 
> # 定期分析：
> # "绍兴特产" 被问了 47 次 → 应该补充到知识库
> # "绍兴酒店推荐" 被问了 32 次 → 应该接入酒店 API
> ```
>
> **这样就形成了数据飞轮：用户的问题反过来驱动知识库的完善。**

### 🔑 得分点总结

```
✅ 你说到了：可能走了 Web Search 降级          — 得分
✅ 你说到了：AI 自检校验                       — 得分
❌ 判断错了："不算幻觉"                        — 扣分（关键！）
❌ 没说到：  没有依据就回答 = 幻觉（即使答对了） — 关键丢分
❌ 没说到：  回答必须标注来源                    — 丢分
❌ 没说到：  前端展示不同来源标签                 — 丢分
❌ 没说到：  Prompt 约束不能用自身知识回答        — 丢分
❌ 没说到：  知识缺口日志（数据飞轮）             — 丢分
```

**评分：4/10**

> **核心教训：幻觉的定义不是"答错了"，而是"没有依据就回答了"。即使碰巧答对了，没有来源也算幻觉。在医疗、法律、金融等严肃场景，这种无依据的回答可能造成严重后果。记住这个定义，这是面试官最爱考的认知点。**
