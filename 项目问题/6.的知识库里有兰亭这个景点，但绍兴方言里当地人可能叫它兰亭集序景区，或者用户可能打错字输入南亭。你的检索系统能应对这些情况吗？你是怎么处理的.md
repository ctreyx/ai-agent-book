### 🎯 满分回答：

> **这个问题我在项目里实际遇到过，分三层来解决：**
>
> ---
>
> **第一层：HyDE 解决别名和口语化表达**
>
> ```
> 用户输入："兰亭集序景区怎么去"
>
> 如果直接拿这句话去向量库检索：
>   → 知识库里存的是"兰亭"不是"兰亭集序景区"
>   → 向量相似度可能不够高
>
> HyDE 的处理：
>   → 先让 LLM 生成一段关于"兰亭集序景区"的假设答案
>   → "兰亭位于绍兴市柯桥区兰亭镇，因王羲之《兰亭集序》得名..."
>   → 这段假设答案里包含了"兰亭"这个标准名称
>   → 用这段文字去检索，就能匹配到知识库里的"兰亭"文档
> ```
>
> **HyDE 天然能处理别名问题，因为 LLM 知道"兰亭集序景区"就是"兰亭"。**
>
> ---
>
> **第二层：BM25 关键词检索兜底**
>
> ```
> 用户输入："兰亭"
>
> 向量检索：语义匹配，能找到 ✅
> BM25：精确匹配"兰亭"两个字，也能找到 ✅
>
> 混合检索的好处：
>   即使向量检索因为别名问题找不准，
>   BM25 只要文档里包含"兰亭"这两个字就能召回
>   两路互补，召回率更高
> ```
>
> ---
>
> **第三层：错别字处理（"南亭"→"兰亭"）**
>
> 这是最难的场景，"南亭"和"兰亭"语义完全不同，向量检索和 BM25 都可能找不到。
>
> ```python
> # 我的处理方案：模糊匹配 + 纠错建议
> 
> # 1. 维护一个景点名称词典
> ATTRACTIONS = [
>     "鲁迅故里", "沈园", "兰亭", "东湖",
>     "柯岩", "安昌古镇", "大禹陵"
> ]
> 
> # 2. 用编辑距离找最相似的景点名
> from difflib import get_close_matches
> 
> def fuzzy_match(user_input: str) -> list:
>     matches = get_close_matches(
>         user_input, 
>         ATTRACTIONS, 
>         n=3, 
>         cutoff=0.5
>     )
>     return matches
> 
> # "南亭" → 匹配到 ["兰亭"]（编辑距离=1）
> # "鲁讯故里" → 匹配到 ["鲁迅故里"]
> ```
>
> ```
> 完整流程：
> 
> 用户输入"南亭怎么去"
>     ↓
> 先走正常检索（HyDE + 混合检索 + Reranker）
>     ↓
> 检索结果 Top1 分数 > 阈值？
>   ├── 是 → 正常回答（说明检索到了）
>   └── 否 → 检索结果不可信
>              ↓
>         用模糊匹配查景点词典
>              ↓
>         找到相似："兰亭"
>              ↓
>         返回提示：
>         "没有找到'南亭'相关信息，
>          您是否想问的是'兰亭'？"
>              ↓
>         用户确认 → 用"兰亭"重新检索
> ```
>
