### 🎯 满分回答：

> **多轮对话管理我做了三件事：指代消解、分级存储、动态压缩。**
>
> ---
>
> **第一件事：指代消解（检索前最关键的一步）**
>
> 你举的这个例子，第二轮"门票多少钱"没有说哪个景点，第三轮"附近有什么好吃的"也没说哪里的附近。如果直接拿这两句话去检索，向量库根本不知道是在问鲁迅故里。
>
> 所以我用了 LangChain 的 **History-Aware Retriever**，检索前自动改写：
>
> ```
> 第一轮："鲁迅故里怎么去"
>   → 不需要改写，直接检索
>
> 第二轮："门票多少钱"
>   → 改写为 "鲁迅故里门票多少钱"
>   → 然后再检索
>
> 第三轮："附近有什么好吃的推荐"
>   → 改写为 "鲁迅故里附近有什么好吃的推荐"
>   → 然后再检索
> ```
>
> **不做这一步，后面检索和回答全废。**
>
> ---
>
> **第二件事：分级存储（热数据 Redis + 冷数据 PostgreSQL）**
>
> ```
> 对话历史不是只存一个地方：
>
> Redis（热存储）：
>   → 存当前活跃会话的最近 10 条消息
>   → 内存读写，毫秒级响应
>   → TTL 30 分钟，过期自动清理
>
> PostgreSQL（冷存储）：
>   → 存完整的对话历史
>   → 持久化，不会丢
>   → 用于回溯分析、优化迭代
>
> 流程：
>   用户发消息 → 先查 Redis 拿最近上下文
>             → Redis 没有 → 查 PostgreSQL
>             → 对话结束 → 写入 PostgreSQL 持久化
> ```
>
> ---
>
> **第三件事：动态压缩（不是每轮都压缩）**
>
> ```
> 压缩策略：
>
> 对话轮数 < 8 轮（16条消息）：
>   → 不压缩，完整历史直接带上
>   → 此时 token 消耗还在可控范围
>
> 对话轮数 >= 8 轮：
>   → 触发 LLM 摘要压缩
>   → 把前面所有历史压缩成一段 200 字左右的摘要
>   → 摘要 + 最近 2 轮完整对话 作为上下文
>   → 总 token 控制在 2000 以内
> ```
>
> ```python
> def get_context(thread_id: str):
>     turn_count = memory.get_turn_count(thread_id)
>     
>     if turn_count < 16:
>         # 不压缩，带完整历史
>         return memory.get_history(thread_id, limit=16)
>     
>     else:
>         # 压缩：摘要 + 最近2轮
>         summary = memory.get_summary(thread_id)
>         if not summary:
>             full_history = memory.get_history(thread_id)
>             summary = llm.invoke(
>                 f"把以下对话压缩成200字摘要：\n{full_history}"
>             ).content
>             memory.save_summary(thread_id, summary)
>         
>         recent = memory.get_history(thread_id, limit=4)
>         
>         return [
>             {"role": "system", "content": f"之前对话摘要：{summary}"},
>             *recent  # 最近2轮完整保留
>         ]
> ```
>
> ---
>
> **用你举的例子走一遍完整流程：**
>
> ```
> 第一轮："鲁迅故里怎么去"
>   上下文：[]（空）
>   检索改写：不需要
>   回答后保存：Redis + PG
>
> 第二轮："门票多少钱"
>   上下文：[第一轮Q+A]（从Redis读）
>   检索改写："鲁迅故里门票多少钱"
>   回答后保存：Redis + PG
>
> 第三轮："附近有什么好吃的推荐"
>   上下文：[第一轮Q+A, 第二轮Q+A]（从Redis读）
>   检索改写："鲁迅故里附近有什么好吃的推荐"
>   回答后保存：Redis + PG
>
> 此时还不到8轮，不触发压缩
> 到第8轮才开始压缩
> ```
>
> **token 消耗控制：**
>
> | 阶段 | 上下文大小 | 策略 |
> |---|---|---|
> | 1-8轮 | 约 500-2000 token | 完整历史，不压缩 |
> | 8轮以上 | 控制在 2000 token 内 | 摘要 + 最近2轮 |
> | 超长对话 | 严格 2000 token | 摘要持续更新 |
