### 🎯 满分回答：

> **这种复杂任务，我的 Agent 会分 5 步处理：**
>
> ---
>
> **第 1 步：澄清缺失信息**
>
> ```
> 用户说："帮我规划两天一夜的绍兴行程，预算2000元"
> 
> Agent 思考：信息不够，需要澄清
>   → 从哪个城市出发？（影响交通方式和费用）
>   → 什么时间去？（影响天气和景区开放）
>   → 有没有偏好？（历史文化？自然风光？美食？）
>   → 几个人去？（影响预算分配）
> 
> Agent 回复：
> "好的！我来帮你规划，先确认几个信息：
>  1. 你从哪个城市出发？
>  2. 打算什么时候去？
>  3. 有什么偏好吗？比如喜欢历史文化还是自然风光？"
> ```
>
> **这一步非常重要，不澄清就瞎规划，结果肯定不靠谱。**
>
> ---
>
> **第 2 步：信息收集（多工具并行调用）**
>
> ```
> 用户确认："从杭州出发，下周六，喜欢历史文化"
> 
> Agent 拆解任务，调用多个工具：
> 
> ┌─────────────────────────────────────────────┐
> │  Tool 1: 天气查询                             │
> │  → 调用天气 API 查下周六绍兴天气               │
> │  → 返回：晴，25°C                             │
> │                                               │
> │  Tool 2: RAG 知识库检索                        │
> │  → 检索历史文化类景点推荐                       │
> │  → 返回：鲁迅故里、沈园、兰亭、大禹陵...       │
> │                                               │
> │  Tool 3: Text2SQL 查询                        │
> │  → 查各景点门票价格、开放时间                   │
> │  → 返回：鲁迅故里免费、沈园40元、兰亭20元...   │
> │                                               │
> │  Tool 4: 交通查询                              │
> │  → 查杭州到绍兴交通方式                        │
> │  → 返回：高铁23分钟/¥24，驾车约1.5小时        │
> └─────────────────────────────────────────────┘
> ```
>
> ---
>
> **第 3 步：LLM 综合规划（核心）**
>
> ```python
> plan_prompt = """
> 根据以下信息，规划两天一夜的绍兴行程。
> 
> 【约束条件】
> - 总预算：2000 元
> - 出发地：杭州
> - 时间：下周六-周日
> - 偏好：历史文化
> - 天气：晴，25°C
> 
> 【可用信息】
> - 交通：{transport_info}
> - 景点：{attractions_info}
> - 票价：{ticket_info}
> 
> 【输出要求】
> 严格按以下 JSON 格式输出：
> {
>   "days": [
>     {
>       "date": "Day 1",
>       "schedule": [
>         {
>           "time": "09:00-11:30",
>           "place": "景点名",
>           "activity": "具体活动",
>           "cost": 0,
>           "longitude": 120.xx,
>           "latitude": 29.xx
>         }
>       ]
>     }
>   ],
>   "budget": {
>     "transport": 48,
>     "tickets": 60,
>     "food": 300,
>     "hotel": 350,
>     "total": 758
>   }
> }
> """
> ```
>
> ---
>
> **第 4 步：预算校验（Agent 自检）**
>
> ```
> Agent 生成行程后自己检查：
> 
> total = transport + tickets + food + hotel
> 
> if total > 2000:
>     → 自动调整：换更便宜的酒店或减少景点
>     → 重新生成
> 
> if total < 1000:
>     → 可以建议升级酒店或加一顿特色餐
> ```
>
> ---
>
> **第 5 步：返回结构化结果，驱动前端渲染**
>
> ```
> Agent 输出 JSON
>     ↓
> 前端解析：
>   → 时间轴组件渲染每个时段的活动
>   → OpenLayers 渲染所有景点 POI 标注
>   → 按顺序连线画出推荐路线
>   → 预算卡片展示费用分配
>   → 弹窗："以下是你的行程规划，是否满意？"
>     → 满意 → 保存
>     → 不满意 → 用户说"沈园换成东湖" → Agent 重新规划
> ```
>
> ---
>
> **在 LangGraph 里的编排：**
>
> ```
> START → 澄清信息 → 用户确认
>            ↓
>        多工具并行调用（天气/RAG/SQL/交通）
>            ↓
>        LLM 综合规划
>            ↓
>        预算校验 → 超预算？→ 是 → 重新规划
>            ↓ 否
>        输出结构化 JSON → 前端渲染
>            ↓
>        用户反馈 → 要调整？→ 是 → 回到规划步骤
>            ↓ 否
>          END
> ```
>
> **这就是 LangGraph 状态图的优势：支持条件分支和循环，预算超了能自动回去重新规划，用户不满意也能回去调整。普通的 Chain 做不到这种动态流程。**
