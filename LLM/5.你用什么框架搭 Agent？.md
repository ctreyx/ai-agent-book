框架太多了，但你只需要记住这个决策树：

你要搭什么级别的 Agent？
    │
    ├── 简单 Agent（单Agent + 几个工具）
    │     └── ✅ LangChain（入门快、生态好）
    │
    ├── 复杂工作流（多步骤、有分支、有状态）
    │     └── ✅ LangGraph（LangChain 官方出品，专门做这个）
    │
    ├── 多 Agent 协作（多个Agent分工）
    │     ├── ✅ LangGraph（官方推荐）
    │     └── ✅ CrewAI（上手更简单，但灵活性差一些）
    │
    └── 企业级生产部署
          └── ✅ LangGraph + LangSmith（监控 + 调试）
各框架定位
框架	定位	一句话
LangChain	基础框架	AI 应用开发的"React"
LangGraph	工作流引擎	复杂 Agent 编排的"Vue Router"
CrewAI	多 Agent 框架	快速搭多 Agent 团队
AutoGen	微软出品	多 Agent 对话协作
Dify	低代码平台	拖拽式搭 Agent，不写代码
Coze	字节出品	国内低代码 Agent 平台
面试完整回答
"我主要用 LangChain + LangGraph 这套组合。

LangChain 负责基础能力：LLM 调用、Prompt 管理、工具封装、RAG 链路，适合搭建简单的单 Agent 应用。

LangGraph 负责复杂编排：当 Agent 需要多步骤、有条件分支、有状态管理、多 Agent 协作的时候，就用 LangGraph 的状态图来编排。它的核心概念是 Node（节点）和 Edge（边），每个节点是一个处理步骤，边定义了流转逻辑，支持条件路由和循环。

选这套的原因有三个：第一，它们是同一个团队出品的，集成最好；第二，社区生态最大，遇到问题好找解决方案；第三，LangSmith 可以做线上监控和调试，方便排查生产问题。

我也了解 CrewAI 和 Dify，CrewAI 搭多 Agent 更快但灵活性不如 LangGraph，Dify 适合非技术人员快速搭建。"

📌 四题总结速记卡
text

① Agent 失控 → Human-in-the-loop
   → 关键操作前暂停等人确认
   → 只读自动执行，写操作必须确认

② Agent vs Workflow
   → Workflow 固定流程，Agent 动态决策
   → 生产中混合使用：大流程固定 + 关键节点灵活

③ 多 Agent 协作
   → 主从 / 顺序 / 辩论 三种模式
   → 公式：Supervisor + 多个专业子 Agent

④ 框架选型
   → LangChain（基础）+ LangGraph（编排）
   → 简单用 LangChain，复杂用 LangGraph
