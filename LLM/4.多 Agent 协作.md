三、多 Agent 协作
🧠 为什么会问这个？
因为复杂任务一个 Agent 搞不定，需要多个 Agent 分工合作。这是 2025-2026 年的热点方向。

💡 核心概念
一个 Agent = 一个员工，多个 Agent = 一个团队

text

你一个人干活    = 单 Agent（什么都自己来）
你带一个团队    = 多 Agent（分工协作）

团队模式：
  ┌─── 项目经理 Agent（总协调）───┐
  │         │          │          │
  ↓         ↓          ↓          ↓
研究员    分析师     写手       审核员
Agent     Agent     Agent      Agent
(查资料)  (分析数据)  (写报告)   (检查质量)
三种常见协作模式
模式一：主从模式（Supervisor）⭐最常用
text

                 主 Agent（Supervisor / 经理）
                 负责分配任务、汇总结果
                    ↑↓        ↑↓        ↑↓
                 子Agent1   子Agent2   子Agent3
                 (搜索)     (分析)     (写作)
Python

# 伪代码
supervisor_prompt = """
你是项目经理，你有3个下属：
- 搜索员：负责搜索信息
- 分析师：负责数据分析
- 写手：负责撰写报告

根据用户需求，你决定先让谁工作，
拿到结果后再分配给下一个人。
"""
就像你在公司里：产品经理把需求拆分，分给不同的开发做，最后汇总。

模式二：顺序模式（Sequential / 流水线）
text

用户输入 → Agent1(研究) → Agent2(分析) → Agent3(写作) → Agent4(审核) → 最终输出
就像工厂的流水线，每个工位干一道工序，依次往下传。

模式三：辩论模式（Debate / 对抗）
text

        用户问题
       ↙       ↘
   Agent A      Agent B
   (正方)       (反方)
       ↘       ↙
     Agent C（裁判）
     综合两方观点
     给出最终答案
适合需要多角度分析的场景，比如投资决策、方案评审。

用你的 GIS 项目举例
text

用户说："分析北京朝阳区适合开奶茶店的位置"

┌─── 总调度 Agent ──────────────────────────────────┐
│                                                    │
│  "这个任务需要3个步骤，我来分配"                      │
│                                                    │
│  ① GIS Agent：                                    │
│     调用地图工具，获取朝阳区的 POI 数据              │
│     分析现有奶茶店分布、人流量、竞争密度              │
│     输出 → 候选位置列表 + 空间分析数据               │
│                  ↓                                 │
│  ② 数据分析 Agent：                                │
│     接收空间数据，分析租金、人流、竞品等因素          │
│     计算每个候选位置的综合评分                       │
│     输出 → 排序后的推荐列表 + 分析报告               │
│                  ↓                                 │
│  ③ 报告生成 Agent：                                │
│     把分析结果写成可读的报告                         │
│     生成地图标注指令（前端渲染用）                    │
│     输出 → 最终报告 + 地图可视化数据                 │
│                                                    │
└────────────────────────────────────────────────────┘

from langgraph.graph import StateGraph

# 定义3个Agent节点
graph = StateGraph(State)

graph.add_node("supervisor",    supervisor_agent)     # 总调度
graph.add_node("gis_agent",     gis_analysis_agent)   # GIS分析
graph.add_node("data_agent",    data_analysis_agent)  # 数据分析
graph.add_node("report_agent",  report_gen_agent)     # 报告生成

# 总调度决定下一步交给谁
graph.add_conditional_edges("supervisor", route_to_agent)

# 每个子Agent完成后回到总调度汇报
graph.add_edge("gis_agent",    "supervisor")
graph.add_edge("data_agent",   "supervisor")
graph.add_edge("report_agent", "supervisor")

app = graph.compile()
面试完整回答
"多 Agent 协作就是把一个复杂任务拆给多个专业化的 Agent 分工完成，每个 Agent 专注一个领域。

常见的协作模式有三种：主从模式（一个 Supervisor 分配任务）、顺序模式（流水线式依次处理）、辩论模式（多角度对抗分析）。生产中最常用的是主从模式。

比如在我的 GIS 项目里，一个总调度 Agent 负责理解用户意图和分配任务，下面有 GIS 分析 Agent 做空间查询、数据分析 Agent 做综合评分、报告生成 Agent 做可视化输出，各自完成后回到总调度汇总。这个用 LangGraph 的状态图来编排，每个 Agent 是一个节点，通过条件边连接。"
