生产环境的长期记忆绝对不能每次都查数据库。我的方案是三级缓存 + 会话级加载 + 异步更新。

三级缓存： L1 进程内存 store 、L2 Redis、L3 数据库。读取时逐级查找，命中就回填上层。大部分请求在 L1 或 L2 就命中了，延迟控制在 3ms 以内。

会话级加载： 不是每轮对话都查库，而是会话开始时加载一次用户画像到内存，整个会话期间直接用内存中的数据。一次会话只查一次缓存，不管聊多少轮。

异步更新： 会话结束后，用 LLM 异步提取本次对话中的新信息更新画像，不阻塞用户。用 BackgroundTasks 或消息队列异步执行。

另外还要注意两个细节：一是画像要做版本控制，防止多端并发覆盖；二是偏好要做时间衰减，最近的权重高，久远的权重低，避免用过时的偏好推荐。

## 七、面试标准回答

> "Agent 记忆分三层：感知记忆、短期记忆、长期记忆。
>
> **短期记忆就是当前会话的上下文。** 核心挑战是 LLM 上下文窗口有限，对话轮次多了会超。常见方案有三种：滑动窗口只保留最近 N 轮，最简单但会丢信息；Token 预算控制，精确但还是会丢；摘要压缩，用 LLM 把早期对话压缩成摘要，既保留关键信息又控制 token，是最推荐的方案。在 LangGraph 中，短期记忆通过 checkpointer + thread_id 实现，每个会话维护独立的 State。
>
> **长期记忆是跨会话持久化的信息。** 主要存用户画像和历史交互摘要。实现方式有两种：一是结构化存储，每次对话后用 LLM 提取用户偏好存入数据库，下次加载画像注入 prompt 实现个性化；二是向量化存储，把历史对话摘要向量化，需要时通过语义检索找到相关记忆。在 LangGraph 中，长期记忆通过 store 实现，和 checkpointer 的短期记忆分开管理。
>
> 两者的关系是：**短期记忆让 Agent 能理解当前对话的上下文，长期记忆让 Agent 能'认识'用户并提供个性化服务。**"

## 三、短期记忆

### 是什么

```
短期记忆 = 当前会话内的对话历史

作用：让 Agent 能理解上下文，知道"第二个"指的是什么
生命周期：一轮会话内有效，会话结束就可以丢弃
存储位置：内存（Redis / LangGraph State / 进程内变量）
```

### 核心挑战

LLM 有上下文窗口限制（比如 GLM-4 是 128K token）。对话轮次多了，历史消息会超出窗口，必须做**裁剪或压缩**。

### 实现方案（从简单到复杂）

#### 方案一：滑动窗口（最常用）

```python
# 只保留最近 N 轮对话
class SlidingWindowMemory:
    def __init__(self, max_rounds: int = 10):
        self.max_rounds = max_rounds
        self.messages: list[dict] = []
    
    def add(self, role: str, content: str):
        self.messages.append({"role": role, "content": content})
        
        # 一轮 = 一问一答 = 2 条消息
        max_messages = self.max_rounds * 2
        if len(self.messages) > max_messages:
            # 保留 system prompt + 最近 N 轮
            self.messages = self.messages[-max_messages:]
    
    def get_messages(self) -> list[dict]:
        return self.messages
```

```
优点：简单，开销小
缺点：早期的重要信息会被丢掉
      比如用户第一轮说了"我带着老人和小孩"，
      滑动窗口可能把这条关键信息滑出去了
```

#### 方案二：Token 预算控制

```python
import tiktoken

class TokenBudgetMemory:
    def __init__(self, max_tokens: int = 4000):
        self.max_tokens = max_tokens
        self.messages: list[dict] = []
        self.encoder = tiktoken.encoding_for_model("gpt-4")
    
    def _count_tokens(self, messages: list[dict]) -> int:
        return sum(
            len(self.encoder.encode(m["content"])) 
            for m in messages
        )
    
    def add(self, role: str, content: str):
        self.messages.append({"role": role, "content": content})
        
        # 从前往后删，直到总 token 数在预算内
        while (
            len(self.messages) > 2 and 
            self._count_tokens(self.messages) > self.max_tokens
        ):
            # 保留第一条（可能是重要的系统设定）和最后几条
            self.messages.pop(1)
```

```
优点：精确控制 token 消耗，不会超出模型上下文窗口
缺点：还是会丢信息
```

#### 方案三：摘要压缩（最推荐）

```python
class SummaryMemory:
    def __init__(self, llm, max_rounds: int = 6):
        self.llm = llm
        self.max_rounds = max_rounds
        self.messages: list[dict] = []
        self.summary: str = ""  # 历史摘要
    
    def add(self, role: str, content: str):
        self.messages.append({"role": role, "content": content})
        
        # 超过 max_rounds 轮时，把早期对话压缩成摘要
        if len(self.messages) > self.max_rounds * 2:
            # 取出要压缩的消息（前面的几轮）
            to_compress = self.messages[:4]  # 压缩最早的 2 轮
            self.messages = self.messages[4:]  # 保留最近的
            
            # 用 LLM 生成摘要
            compress_prompt = f"""
请将以下对话历史压缩成一段简洁的摘要，保留关键信息：
- 用户的核心需求和偏好
- 已经讨论过的景点
- 用户提到的约束条件（时间、人数、预算等）

当前摘要：{self.summary}

需要压缩的对话：
{self._format_messages(to_compress)}
"""
            self.summary = self.llm.invoke(compress_prompt)
    
    def get_messages(self) -> list[dict]:
        messages = []
        
        # 先放摘要
        if self.summary:
            messages.append({
                "role": "system",
                "content": f"之前的对话摘要：{self.summary}"
            })
        
        # 再放最近的完整对话
        messages.extend(self.messages)
        
        return messages
```

```
优点：既保留了关键信息，又控制了 token 消耗
缺点：摘要本身要调一次 LLM，有额外延迟和 token 消耗
适用：对话轮次多的场景（客服、陪聊、复杂规划）
```

## 四、长期记忆

### 是什么

```
长期记忆 = 跨会话持久化的信息

作用：让 Agent "认识"用户，记住用户的偏好和历史
生命周期：跨会话、长期存在
存储位置：数据库（PostgreSQL / MongoDB / 向量数据库）
```

### 长期记忆存什么

```
┌─────────────────────────────────────────────────┐
│                  长期记忆内容                      │
│                                                  │
│  ① 用户画像                                      │
│     - 姓名、年龄段、出行偏好                       │
│     - "带着老人和小孩" → 推荐无障碍路线            │
│     - "喜欢历史文化" → 优先推荐人文景点             │
│                                                  │
│  ② 历史交互摘要                                   │
│     - 上次来过哪些景点                             │
│     - 上次问过什么问题                             │
│     - 上次的满意度如何                             │
│                                                  │
│  ③ 用户反馈                                       │
│     - 点赞/踩过哪些回答                            │
│     - 明确说过"我不喜欢爬山"                       │
│                                                  │
│  ④ 事实性知识                                     │
│     - Agent 在交互中学到的新信息                    │
│     - 比如用户告诉 Agent "这个景点最近在维修"       │
│                                                  │
└─────────────────────────────────────────────────┘
```

### 实现方案

#### 方案一：结构化存储（用户画像）

```python
# 用数据库存储用户画像
# 每次对话结束后，用 LLM 提取关键信息更新画像

class UserProfile:
    """用户画像 - 存在 PostgreSQL / MongoDB"""
    user_id: str
    preferences: dict       # {"喜欢": ["历史文化", "美食"], "不喜欢": ["爬山"]}
    constraints: dict       # {"同行人": "老人和小孩", "预算": "中等"}
    visited_spots: list     # ["鲁迅故里", "沈园"]
    last_visit_date: str
    interaction_count: int


class LongTermMemory:
    def __init__(self, db, llm):
        self.db = db
        self.llm = llm
    
    # 对话结束后，提取关键信息更新画像
    async def update_after_session(
        self, 
        user_id: str, 
        conversation: list[dict]
    ):
        current_profile = await self.db.get_profile(user_id)
        
        extract_prompt = f"""
根据以下对话，提取用户的关键信息，用于更新用户画像。
只提取明确表达的信息，不要推测。

当前画像：{current_profile}

本次对话：
{self._format_conversation(conversation)}

请输出 JSON 格式：
{{
    "new_preferences": [],        // 新发现的喜好
    "new_constraints": {{}},       // 新发现的约束
    "visited_spots": [],          // 本次提到去过的景点
    "feedback": []                // 对回答的正面/负面反馈
}}
"""
        extracted = self.llm.invoke(extract_prompt)
        
        # 合并到现有画像
        await self.db.update_profile(user_id, extracted)
    
    # 对话开始时，加载用户画像作为上下文
    async def get_context(self, user_id: str) -> str:
        profile = await self.db.get_profile(user_id)
        
        if not profile:
            return ""
        
        return f"""
该用户的历史信息：
- 偏好：{profile.preferences}
- 约束：{profile.constraints}
- 去过的景点：{profile.visited_spots}
- 历史交互次数：{profile.interaction_count}

请根据以上信息个性化回答。
"""
```

#### 方案二：向量化存储（历史对话检索）

```python
# 把历史对话摘要向量化存储
# 需要时通过语义检索找到相关的历史记忆

from langchain_community.vectorstores import FAISS
from langchain_community.embeddings import ZhipuAIEmbeddings


class VectorLongTermMemory:
    def __init__(self):
        self.embeddings = ZhipuAIEmbeddings()
        # 每个用户一个向量空间
        self.user_stores: dict[str, FAISS] = {}
    
    # 每次会话结束后，把摘要存入向量库
    async def save_session_summary(
        self, 
        user_id: str, 
        summary: str,
        metadata: dict  # {"date": "2026-09-14", "topic": "西湖游览"}
    ):
        if user_id not in self.user_stores:
            self.user_stores[user_id] = FAISS.from_texts(
                [summary], self.embeddings, metadatas=[metadata]
            )
        else:
            self.user_stores[user_id].add_texts(
                [summary], metadatas=[metadata]
            )
    
    # 新对话开始时，检索相关的历史记忆
    async def recall(
        self, 
        user_id: str, 
        current_query: str, 
        top_k: int = 3
    ) -> list[str]:
        if user_id not in self.user_stores:
            return []
        
        # 用当前问题检索最相关的历史记忆
        docs = self.user_stores[user_id].similarity_search(
            current_query, k=top_k
        )
        
        return [doc.page_content for doc in docs]
```

```
使用场景：
  用户上次来过一次绍兴，问过西湖路线
  这次又来了，问"上次你给我推荐的那个路线是什么来着"
  
  → 用当前问题检索历史记忆
  → 找到上次的对话摘要
  → Agent 能回答"上次推荐的是..."
```

#### 方案三：LangGraph 的 Store（2024 年底新增的能力）


## 五、短期记忆 vs 长期记忆 完整对比

| 维度 | 短期记忆 | 长期记忆 |
|------|---------|---------|
| **存什么** | 当前对话的历史消息 | 用户画像、历史偏好、跨会话知识 |
| **生命周期** | 一轮会话 | 永久（或设过期时间） |
| **作用** | 理解上下文（"第二个"是什么） | 个性化（"你上次喜欢历史景点"） |
| **存在哪** | 内存 / Redis | 数据库 / 向量数据库 |
| **粒度** | thread_id（会话级） | user_id（用户级） |
| **容量限制** | 受 LLM 上下文窗口限制 | 理论上无限 |
| **处理方式** | 滑动窗口 / token 预算 / 摘要压缩 | 结构化存储 / 向量检索 |
| **LangGraph 实现** | checkpointer | store |
| **你的项目** | thread_id + State 中的上下文 | 暂未实现（可以说是下一步规划） |

> **长期记忆是跨会话持久化的信息。** 主要存用户画像和历史交互摘要。实现方式有两种：一是结构化存储，每次对话后用 LLM 提取用户偏好存入数据库，下次加载画像注入 prompt 实现个性化；二是向量化存储，把历史对话摘要向量化，需要时通过语义检索找到相关记忆。在 LangGraph 中，长期记忆通过 store 实现，和 checkpointer 的短期记忆分开管理。
>
> 两者的关系是：**短期记忆让 Agent 能理解当前对话的上下文，长期记忆让 Agent 能'认识'用户并提供个性化服务。**"
