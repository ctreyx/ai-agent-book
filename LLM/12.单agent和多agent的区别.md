


# 单agent的场景最优
1. 推理次数1-5次任务调用，逻辑链路已知并且线性执行
2. 延迟和成本更优，单体架构没协商成本，延迟低消耗低
3. 权威表示，在纯顺序推理，多agent性能下降40-70%，就是任务a做完做b，b做完c，强行拆多agent性能更低

# 多agent的场景
1. 上下文工具饱和，所有历史记录堆在一个上下文
2. 注意力稀释，system prompt写的又长又多，导致模型无法专注，注意力被稀释
3. 角色冲突，要模型又保守又激进，到最后就是摇摆不定
4. 故障爆炸半径，单agent一个出错整个链路出错，多agent一个出错可以优雅降级


# 对比

1. 上下文：
单agent: 所有历史调用混在一起，上下文污染
多agent: 每个agent独立上下文，互不污染

2. 提示词
单agent:一个提示词覆盖全部，又长又臭
多agent:每个有专属提示词角色，精准聚焦

3. 工具调用
单agent:只能串行，工具逐个调用
多agent:每个独立运行，延迟低

4. 出错
单:一个错全部报错
多：一个错，不影响其他
