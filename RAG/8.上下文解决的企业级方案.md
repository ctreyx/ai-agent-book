# 多轮对话 RAG 的企业级解决方案全解析

---

## 🎯 第一个问题：Query Rewriting 每个 RAG 都要做吗？

### 直接回答：不是

```
看你的产品形态：

单轮问答（用户每次独立提问）
  → 比如：搜索框、知识库查询页面
  → ❌ 不需要 Query Rewriting
  → 每个问题都是完整独立的

多轮对话（聊天模式，有上下文）
  → 比如：客服机器人、医疗问诊助手
  → ✅ 必须做 Query Rewriting
  → 不做的话第二轮开始就会出问题
```

**判断标准就一个：你的产品有没有"连续对话"功能？有就要做。**

---

## 🔥 第二个问题：企业级解决方案有哪些？

一共有 **4 种主流方案**，从简单到复杂：

---

### 方案一：Query Rewriting（查询改写）⭐ 最主流

就是上一题讲的，用 LLM 把指代还原：

```python
# "它能和布洛芬一起吃吗" → "阿司匹林能和布洛芬一起吃吗"

rewrite_prompt = """
根据对话历史，把用户最新的问题改写成独立完整的问题。
把所有代词（它、这个、那个）替换成具体名词。

对话历史：
{chat_history}

最新问题：{current_question}

改写后：
"""
```

| 优点 | 缺点 |
|---|---|
| 实现简单，效果好 | 多一次 LLM 调用，增加延迟 |
| 适用范围广 | 改写质量依赖 LLM 能力 |

**适合：80% 的多轮对话 RAG 场景**

---

### 方案二：History-Aware Retriever（LangChain 官方方案）⭐⭐ 推荐

LangChain 已经把 Query Rewriting 封装好了，不用自己写 Prompt：

```python
from langchain.chains import create_history_aware_retriever
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

llm = ChatOpenAI(model="deepseek-v4-flash", ...)

# LangChain 内置的改写 Prompt
contextualize_prompt = ChatPromptTemplate.from_messages([
    ("system", "根据对话历史，把用户最新的问题改写成独立的问题。"),
    MessagesPlaceholder("chat_history"),   # 自动注入历史
    ("human", "{input}"),
])

# 一行代码搞定！
history_aware_retriever = create_history_aware_retriever(
    llm=llm,
    retriever=ensemble_retriever,   # 你现有的混合检索器
    prompt=contextualize_prompt,
)

# 使用
from langchain_core.messages import HumanMessage, AIMessage

chat_history = [
    HumanMessage(content="阿司匹林有什么副作用？"),
    AIMessage(content="阿司匹林可能引起胃肠道不适..."),
]

# 它内部会自动：
# 1. 根据历史改写 "它能和布洛芬一起吃吗" → "阿司匹林能和布洛芬一起吃吗"
# 2. 用改写后的问题去检索
results = history_aware_retriever.invoke({
    "input": "它能和布洛芬一起吃吗",
    "chat_history": chat_history,
})
```

**这是目前企业里最常用的方案，LangChain 官方推荐。**

| 优点 | 缺点 |
|---|---|
| 官方封装，代码量少 | 底层还是 Query Rewriting |
| 和 LangChain 生态无缝集成 | 还是多一次 LLM 调用 |

---

### 方案三：对话历史直接拼入检索（简单粗暴）

不做改写，直接把最近几轮对话拼到检索查询里：

```python
# 把最近2轮对话 + 当前问题拼在一起做检索
recent_history = "用户：阿司匹林有什么副作用？\n助手：阿司匹林可能引起胃肠道不适..."
current = "它能和布洛芬一起吃吗"
search_query = recent_history + "\n" + current

# 整段话一起去检索
docs = ensemble_retriever.invoke(search_query)
```

| 优点 | 缺点 |
|---|---|
| 最简单，不需要额外 LLM 调用 | 检索文本太长，噪声多 |
| 零延迟增加 | 向量化长文本效果不稳定 |
| 适合快速原型 | 不适合生产环境 |

**适合：Demo / 原型验证，不推荐生产使用**

---

### 方案四：Contextual Compression + Memory（企业级完整方案）⭐⭐⭐

大厂的做法是把 **记忆管理 + 查询改写 + 检索 + 生成** 全部串成一条链：

```python
from langchain.chains import create_retrieval_chain
from langchain.chains.combine_documents import create_stuff_documents_chain
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

llm = ChatOpenAI(model="deepseek-v4-flash", ...)

# Step 1: 历史感知检索器（自动改写 + 检索）
contextualize_prompt = ChatPromptTemplate.from_messages([
    ("system", "根据对话历史，把用户的问题改写成独立问题。"),
    MessagesPlaceholder("chat_history"),
    ("human", "{input}"),
])

history_aware_retriever = create_history_aware_retriever(
    llm, ensemble_retriever, contextualize_prompt
)

# Step 2: 回答生成链
answer_prompt = ChatPromptTemplate.from_messages([
    ("system", """你是医疗知识助手。根据以下参考资料回答问题。
如果资料中没有相关信息，请说"暂无相关资料"。

参考资料：
{context}"""),
    MessagesPlaceholder("chat_history"),
    ("human", "{input}"),
])

question_answer_chain = create_stuff_documents_chain(llm, answer_prompt)

# Step 3: 完整 RAG 链（改写 + 检索 + 生成 一条龙）
rag_chain = create_retrieval_chain(
    history_aware_retriever,
    question_answer_chain,
)

# ========== 使用 ==========
chat_history = []

# 第一轮
response1 = rag_chain.invoke({
    "input": "阿司匹林有什么副作用？",
    "chat_history": chat_history,
})
print(response1["answer"])

# 更新历史
chat_history.append(HumanMessage(content="阿司匹林有什么副作用？"))
chat_history.append(AIMessage(content=response1["answer"]))

# 第二轮（"它"会被自动改写成"阿司匹林"）
response2 = rag_chain.invoke({
    "input": "它能和布洛芬一起吃吗？",
    "chat_history": chat_history,
})
print(response2["answer"])  # ✅ 正确理解"它"是阿司匹林
```

**这套方案的完整流程：**

```
用户第二轮："它能和布洛芬一起吃吗"
    ↓
history_aware_retriever：
    1. 读取 chat_history
    2. LLM 自动改写 → "阿司匹林能和布洛芬一起吃吗"
    3. 用改写后的问题去混合检索
    4. 返回相关文档
    ↓
question_answer_chain：
    5. 把文档 + 对话历史 + 当前问题喂给 LLM
    6. 生成最终回答
    ↓
"阿司匹林和布洛芬都属于NSAIDs，一般不建议同时服用..."
```

## 📊 四种方案对比

| 方案 | 复杂度 | 效果 | 延迟 | 适用场景 |
|---|---|---|---|---|
| **Query Rewriting（手写）** | ⭐⭐ | ⭐⭐⭐⭐ | +1-2秒 | 灵活定制 |
| **History-Aware Retriever** | ⭐ | ⭐⭐⭐⭐ | +1-2秒 | 🏆 企业首选 |
| **历史直接拼接** | ⭐ | ⭐⭐ | 无增加 | 原型/Demo |
| **完整 RAG Chain** | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | +1-2秒 | 🏆 生产级 |

## 📌 总结

```
Query Rewriting 是不是每个 RAG 都要做？
  → 不是。只有多轮对话场景才需要。

企业级方案推荐：
  → LangChain 的 History-Aware Retriever（最主流）
  → 底层原理还是 Query Rewriting，只是框架帮你封装好了

你需要做的：
```
