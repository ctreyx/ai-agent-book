如果是检索出了问题（找到的文档不对），从前往后排查：

排查点	具体检查	解决方案
数据源	知识库里有没有这个问题的答案？	补充文档
切片	答案有没有被切断成两个 chunk？	调整 chunk_size / overlap
Embedding	向量化是否丢失了关键语义？	换更好的 Embedding 模型
检索方式	纯向量检索是否漏掉了关键词？	加 BM25 混合检索
指代问题	多轮对话中有没有代词没解析？	加 Query Rewriting
如果是生成出了问题（文档对了但回答错了），排查：

排查点	具体检查	解决方案
Prompt	系统提示词有没有要求"只根据资料回答"？	加限制指令
上下文太多	喂了太多无关文档干扰 LLM？	加 Reranker 精筛
上下文太少	只给了1段，信息不够？	增加 top_k
模型能力	模型太弱理解不了？	换更强的模型

### 用指标快速定位问题

```
情况1：Context Recall 低 + 其他正常
  → 检索漏了文档
  → 解决：优化切片 / 加 HyDE / 加 BM25

情况2：Context Precision 低 + 其他正常
  → 检索到了但噪声多
  → 解决：加 Reranker / 减小 top_k

情况3：Faithfulness 低 + Context 指标正常
  → 文档找对了但 LLM 瞎编
  → 解决：优化 Prompt / 加"只根据资料回答"限制

情况4：Answer Relevancy 低 + 其他正常
  → LLM 回答跑题了
  → 解决：优化 Prompt / 换更强的模型
```

## 第一层：全链路可观测（LangSmith）⭐ 企业标配

### LangSmith 是什么？

```
LangSmith = RAG 系统的"Chrome DevTools"

你做前端：F12 打开 DevTools 看网络请求、看 DOM、看性能
做 RAG：打开 LangSmith 看每一步的输入输出、耗时、token 消耗
```

## 第二层：量化评估指标（RAGAS 框架）⭐⭐ 核心

### RAGAS 是什么？

```
RAGAS = RAG Assessment（RAG 评估框架）

它用 LLM 自动给你的 RAG 系统打分
不需要人工一条一条看
```

### 四个核心指标

```
                    用户问题
                   ↙        ↘
             检索环节         生成环节
            ↙      ↘        ↙      ↘
    Context         Context   Faithful-   Answer
    Precision       Recall    ness        Relevancy
    上下文精确度     上下文召回率  忠实度      答案相关性
```

| 指标 | 衡量什么 | 通俗解释 | 分数低说明什么 |
|---|---|---|---|
| **Context Precision** | 检索到的文档有多少是相关的 | 找回来10条，8条相关 = 0.8 | 检索噪声大，喂了无关内容给 LLM |
| **Context Recall** | 该找到的文档找到了多少 | 应该找到5条，实际找到4条 = 0.8 | 检索漏了关键信息 |
| **Faithfulness** | 回答是否忠于检索到的内容 | 回答有没有超出参考资料瞎编 | LLM 产生幻觉了 |
| **Answer Relevancy** | 回答是否切题 | 回答的内容和用户问题相关吗 | LLM 跑题了 |

### 用指标快速定位问题

```
情况1：Context Recall 低 + 其他正常
  → 检索漏了文档
  → 解决：优化切片 / 加 HyDE / 加 BM25

情况2：Context Precision 低 + 其他正常
  → 检索到了但噪声多
  → 解决：加 Reranker / 减小 top_k

情况3：Faithfulness 低 + Context 指标正常
  → 文档找对了但 LLM 瞎编
  → 解决：优化 Prompt / 加"只根据资料回答"限制

情况4：Answer Relevancy 低 + 其他正常
  → LLM 回答跑题了
  → 解决：优化 Prompt / 换更强的模型
```

### 代码实现

```python
# pip install ragas

from ragas import evaluate
from ragas.metrics import (
    context_precision,
    context_recall,
    faithfulness,
    answer_relevancy,
)
from datasets import Dataset

# 准备评估数据集
eval_data = {
    "question": [
        "阿司匹林有哪些副作用？",
        "布洛芬的用法用量是什么？",
        # ... 准备 20-50 条
    ],
    "answer": [
        # 你的 RAG 系统生成的回答
        "阿司匹林可能引起胃肠道不适...",
        "布洛芬建议每6小时服用一次...",
    ],
    "contexts": [
        # 你的 RAG 系统检索到的文档
        ["阿司匹林可能引起胃肠道不适、恶心...", "长期使用需注意..."],
        ["布洛芬规格200mg，每6小时一次...", "肾功能不全禁用..."],
    ],
    "ground_truth": [
        # 人工标注的标准答案（用于计算 recall）
        "阿司匹林的副作用包括胃肠道不适、恶心、呕吐...",
        "布洛芬200mg，每6小时一次，每日不超过4次...",
    ],
}

dataset = Dataset.from_dict(eval_data)

# 一行代码跑评估！
results = evaluate(
    dataset,
    metrics=[
        context_precision,
        context_recall,
        faithfulness,
        answer_relevancy,
    ],
)

print(results)
# {
#   'context_precision': 0.85,    ← 检索精度还行
#   'context_recall': 0.62,       ← ⚠️ 召回率偏低！需要优化检索
#   'faithfulness': 0.93,         ← LLM 基本没瞎编
#   'answer_relevancy': 0.88,     ← 回答基本切题
# }
```

### 一眼就能看出问题

```
你的 RAGAS 得分：
  Context Precision:  0.85  ✅ 没问题
  Context Recall:     0.62  ❌ 太低了！有 38% 的关键文档没找到
  Faithfulness:       0.93  ✅ 不错
  Answer Relevancy:   0.88  ✅ 可以

诊断：问题出在检索召回率
处方：加 HyDE / 加 BM25 / 优化切片 / 加 Query Rewriting

优化后再跑一次 RAGAS，看 Context Recall 是否提升
```

## 第三层：自动化评估流水线 ⭐⭐⭐ 高级

### 把评估变成 CI/CD 的一部分

```
每次改代码后自动跑评估，就像前端跑单元测试一样

你改了切片策略 → 自动跑 RAGAS → 分数提升了 → 合并代码 ✅
你换了 Embedding → 自动跑 RAGAS → 分数下降了 → 阻止合并 ❌
```

## 📊 三层方法总结

| 层级 | 方法 | 作用 | 成本 |
|---|---|---|---|
| **第一层** | LangSmith 全链路追踪 | 看到每一步的输入输出，快速定位 | 低（2行代码） |
| **第二层** | RAGAS 量化评估 | 用数字衡量检索和生成质量 | 中（需要标注数据） |
| **第三层** | 自动化评估流水线 | 每次改动自动验证质量 | 高（需要完善测试集） |

```
你现在应该做到的：
  ✅ 第一层：LangSmith 接入（2行代码搞定）
  ✅ 第二层：RAGAS 跑一次评估（了解四个指标）

面试时说出来就加分的：
  ⭐ 第三层：知道可以做自动化评估流水线
```
