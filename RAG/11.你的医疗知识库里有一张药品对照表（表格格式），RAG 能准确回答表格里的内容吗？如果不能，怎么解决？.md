# 你的医疗知识库里有一张药品对照表（表格格式），RAG 能准确回答表格里的内容吗？如果不能，怎么解决？

# RAG 处理表格数据的企业级解决方案

---

## 🧠 先搞清楚：为什么表格对 RAG 是难题？

### 看看你的切片器对表格做了什么

```
原始文档里的表格：
| 药品名称 | 规格    | 用法用量       | 禁忌             |
|---------|--------|---------------|-----------------|
| 阿司匹林 | 100mg  | 每日一次       | 胃溃疡患者禁用    |
| 布洛芬   | 200mg  | 每6小时一次    | 肾功能不全禁用    |

经过 RecursiveCharacterTextSplitter 切片后：
chunk1: "| 药品名称 | 规格 | 用法用量 | 禁忌 |\n|----"
chunk2: "----|\n| 阿司匹林 | 100mg | 每日一次 | 胃溃疡"
chunk3: "患者禁用 |\n| 布洛芬 | 200mg | 每6小时一次"

💀 表格被切碎了！
```

### 切碎后会怎样？

```
用户问："阿司匹林的规格是多少？"

检索到 chunk2："| 阿司匹林 | 100mg | 每日一次 | 胃溃疡"

问题1：没有表头！LLM 不知道 "100mg" 是规格还是用量
问题2：行被截断了！"胃溃疡"后面的"患者禁用"在另一个 chunk
问题3：LLM 只能猜测，回答不稳定
```

**核心矛盾：表格是二维结构（行+列），但切片器只能处理一维文本。**

---

## 🔥 五种企业级解决方案

---

### 方案一：表格转自然语言 ⭐⭐⭐ 最简单最实用

**思路：在入库之前，把表格的每一行转成一句完整的话**

```python
# 原始表格
table = [
    {"药品名称": "阿司匹林", "规格": "100mg", "用法用量": "每日一次", "禁忌": "胃溃疡患者禁用"},
    {"药品名称": "布洛芬", "规格": "200mg", "用法用量": "每6小时一次", "禁忌": "肾功能不全禁用"},
]

# 每一行转成自然语言
for row in table:
    text = (
        f"{row['药品名称']}的规格为{row['规格']}，"
        f"用法用量为{row['用法用量']}，"
        f"禁忌：{row['禁忌']}。"
    )
    print(text)

# 输出：
# "阿司匹林的规格为100mg，用法用量为每日一次，禁忌：胃溃疡患者禁用。"
# "布洛芬的规格为200mg，用法用量为每6小时一次，禁忌：肾功能不全禁用。"
```

**转换后的文本，切片器怎么切都不会丢信息！**

```
用户问："阿司匹林的规格是多少？"
检索到："阿司匹林的规格为100mg，用法用量为每日一次，禁忌：胃溃疡患者禁用。"
LLM 回答："阿司匹林的规格是100mg" ✅ 完美
```

| 优点 | 缺点 |
|---|---|
| 实现最简单 | 需要提前处理表格 |
| 效果最稳定 | 大表格会生成很多条文本 |
| 适合所有 RAG 系统 | 丢失了表格的对比关系 |

**适合：表格不太大（几十到几百行）的场景**

### 方案二：用 LLM 自动转换表格 ⭐⭐⭐ 推荐

**方案一需要手动写转换代码，这个方案让 LLM 自动做**

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="deepseek-v4-flash", ...)

table_text = """
| 药品名称 | 规格 | 用法用量 | 禁忌 |
|---------|------|---------|------|
| 阿司匹林 | 100mg | 每日一次 | 胃溃疡患者禁用 |
| 布洛芬   | 200mg | 每6小时一次 | 肾功能不全禁用 |
"""

prompt = f"""
请把下面的表格转换成自然语言描述。
要求：
1. 每一行数据转成一段独立完整的描述
2. 必须包含表头信息（列名）作为上下文
3. 每段描述之间用空行分隔

表格内容：
{table_text}
"""

result = llm.invoke(prompt)
print(result.content)

# 输出：
# 阿司匹林：规格为100mg，用法用量为每日一次，禁忌症为胃溃疡患者禁用。
#
# 布洛芬：规格为200mg，用法用量为每6小时一次，禁忌症为肾功能不全禁用。
```

**好处：不管什么格式的表格，LLM 都能转成自然语言**

### 方案三：表头绑定切片法 ⭐⭐⭐⭐ 更优雅

**核心思路：切片时，每个 chunk 都带上表头**

```python
def split_table_with_headers(table_text: str) -> list[str]:
    """
    把表格按行切片，每个 chunk 都带上表头
    """
    lines = table_text.strip().split("\n")
    
    # 提取表头（前两行：标题行 + 分隔行）
    header = lines[0]       # | 药品名称 | 规格 | 用法用量 | 禁忌 |
    separator = lines[1]    # |---------|------|---------|------|
    
    # 每一行数据都和表头拼在一起
    chunks = []
    for data_line in lines[2:]:
        chunk = f"{header}\n{separator}\n{data_line}"
        chunks.append(chunk)
    
    return chunks

# 结果：
# chunk1:
# | 药品名称 | 规格 | 用法用量 | 禁忌 |
# |---------|------|---------|------|
# | 阿司匹林 | 100mg | 每日一次 | 胃溃疡患者禁用 |

# chunk2:
# | 药品名称 | 规格 | 用法用量 | 禁忌 |
# |---------|------|---------|------|
# | 布洛芬   | 200mg | 每6小时一次 | 肾功能不全禁用 |
```

**每个 chunk 都是"表头 + 数据行"的完整小表格，LLM 一看就懂**

### 方案四：Text2SQL 方案 ⭐⭐⭐⭐⭐ 大表格最佳

**思路完全不同：不用向量检索，而是把表格存到 SQL 数据库，让 LLM 写 SQL 查询**

```
传统 RAG 路线：
  用户问题 → 向量检索 → 找文档 → LLM 生成回答
  ❌ 表格数据不适合向量检索

Text2SQL 路线：
  用户问题 → LLM 生成 SQL → 查数据库 → LLM 用查询结果回答
  ✅ 表格数据天然适合 SQL 查询
```

```python
import sqlite3
from langchain_openai import ChatOpenAI

# 1. 表格数据存入 SQLite
conn = sqlite3.connect("medical.db")
cursor = conn.cursor()

cursor.execute("""
CREATE TABLE IF NOT EXISTS drugs (
    name TEXT,
    spec TEXT,
    dosage TEXT,
    contraindication TEXT
)
""")

cursor.executemany("INSERT INTO drugs VALUES (?, ?, ?, ?)", [
    ("阿司匹林", "100mg", "每日一次", "胃溃疡患者禁用"),
    ("布洛芬", "200mg", "每6小时一次", "肾功能不全禁用"),
    ("对乙酰氨基酚", "500mg", "每4-6小时一次", "肝功能异常禁用"),
])
conn.commit()

# 2. 让 LLM 根据用户问题生成 SQL
llm = ChatOpenAI(model="deepseek-v4-flash", ...)

question = "阿司匹林的规格是多少？"

sql_prompt = f"""
你是 SQL 专家。根据用户问题，写一条 SQL 查询语句。

表结构：
drugs(name, spec, dosage, contraindication)
- name: 药品名称
- spec: 规格
- dosage: 用法用量
- contraindication: 禁忌

用户问题：{question}

只输出 SQL 语句，不要解释：
"""

sql = llm.invoke(sql_prompt).content.strip()
print(f"生成的SQL: {sql}")
# 输出: SELECT spec FROM drugs WHERE name = '阿司匹林'

# 3. 执行 SQL
result = cursor.execute(sql).fetchall()
print(f"查询结果: {result}")
# 输出: [('100mg',)]

# 4. 让 LLM 用查询结果生成自然语言回答
answer_prompt = f"""
用户问题：{question}
数据库查询结果：{result}
请用自然语言回答用户问题。
"""

answer = llm.invoke(answer_prompt).content
print(answer)
# 输出: "阿司匹林的规格是100mg。"
```

**Text2SQL 的威力：能处理 RAG 做不到的复杂查询**

```
RAG 能回答：
  "阿司匹林的规格是多少？"          ✅ 简单查找

RAG 很难回答，但 Text2SQL 轻松搞定：
  "哪些药每天只吃一次？"            → SELECT * FROM drugs WHERE dosage LIKE '%每日一次%'
  "规格最大的药是哪个？"            → SELECT name FROM drugs ORDER BY spec DESC LIMIT 1
  "有几种药胃溃疡患者不能吃？"       → SELECT COUNT(*) FROM drugs WHERE contraindication LIKE '%胃%'
  "对比阿司匹林和布洛芬的禁忌"       → SELECT name, contraindication FROM drugs WHERE name IN (...)
```

| 优点 | 缺点 |
|---|---|
| 精确查询，100%准确 | 需要提前把表格导入数据库 |
| 能做聚合、对比、排序 | LLM 生成的 SQL 可能有错 |
| 适合大表格（几万行） | 需要做 SQL 安全防护 |

### 方案五：混合架构（RAG + Text2SQL）⭐⭐⭐⭐⭐ 终极方案

**真实企业项目：文档和表格都有，需要混合处理**

```
用户问题
   ↓
意图识别（Router Agent）
   ↓
┌──────────┬──────────────┐
│          │              │
↓          ↓              ↓
文档类问题   表格类问题      混合类问题
"副作用    "规格多少？"    "100mg的药有
有哪些？"                  哪些副作用？"
   ↓          ↓              ↓
  RAG       Text2SQL      两个都调
   ↓          ↓              ↓
  结果1      结果2          合并结果
   └──────────┴──────────────┘
                ↓
          LLM 生成最终回答
```

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="deepseek-v4-flash", ...)

def route_question(question: str) -> str:
    """让 LLM 判断问题应该走哪条路线"""
    
    route_prompt = f"""
    判断用户问题应该用哪种方式回答：
    
    - "rag"：问题涉及描述性内容，如副作用、作用机制、注意事项
    - "sql"：问题涉及精确数据查询，如规格、价格、用量、数量统计、对比
    - "both"：问题同时涉及以上两类
    
    只输出 rag / sql / both，不要解释。
    
    用户问题：{question}
    """
    
    return llm.invoke(route_prompt).content.strip()

# 使用
question = "阿司匹林的规格是多少？"
route = route_question(question)
# 输出: "sql"

question = "阿司匹林有哪些副作用？"
route = route_question(question)
# 输出: "rag"

question = "规格100mg的药有哪些副作用？"
route = route_question(question)
# 输出: "both"

# 根据路由结果，调用不同的检索方式
if route == "rag":
    answer = rag_chain.invoke(question)
elif route == "sql":
    answer = text2sql_chain.invoke(question)
elif route == "both":
    rag_result = rag_chain.invoke(question)
    sql_result = text2sql_chain.invoke(question)
    answer = merge_and_generate(rag_result, sql_result, question)
```

## 📊 五种方案对比

| 方案 | 复杂度 | 效果 | 适用场景 | 推荐度 |
|---|---|---|---|---|
| **表格转自然语言（手动）** | ⭐ | ⭐⭐⭐ | 小表格、快速解决 | 初级 |
| **LLM 自动转换** | ⭐⭐ | ⭐⭐⭐⭐ | 各类表格 | 中级 |
| **表头绑定切片** | ⭐⭐ | ⭐⭐⭐⭐ | Markdown 表格 | 中级 |
| **Text2SQL** | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 大表格、精确查询 | 高级 |
| **混合架构** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 文档+表格混合 | 企业级 |
