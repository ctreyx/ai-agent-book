# 🎯 面试场景：请你解释一下什么是 RAG？它解决了 LLM 的什么问题？

💬 这样回答：
RAG 全称是 Retrieval Augmented Generation，中文叫检索增强生成。

它主要解决了 LLM 的两个核心问题：

第一个是幻觉问题。 LLM 在训练完之后，知识就固定了，遇到不知道的问题它会倾向于"猜"一个答案，也就是我们说的幻觉。RAG 通过让 AI 先查资料再回答，有据可查就不会瞎编。

第二个是私有数据问题。 LLM 只知道训练时学过的公开数据，但它不知道我们公司内部的文档、产品手册、用户数据这些私有信息。RAG 可以把这些私有数据接进来，让 AI 能回答私有领域的问题。

它的核心流程分五步：

text

1. 文档准备   → 把私有文档（PDF/TXT/Word）加载进来
2. 文档切片   → 把长文档切成小段 chunk
3. 向量化     → 用 Embedding 模型把每段文字转成向量（数字指纹）
4. 存入向量库 → 把向量存到向量数据库，比如 Chroma、FAISS
5. 检索生成   → 用户提问时，把问题也转成向量，
                去向量库找最相似的几段，
                把这几段内容 + 用户问题一起喂给 LLM，
                LLM 基于这些内容生成最终回答
用一句话总结就是：

RAG 让 AI 从"靠记忆瞎猜"变成"先查资料再回答"，解决了幻觉和私有数据两个核心痛点。


# 什么是RAG系统?如何设计优化RAG架构

面试官：请你说一下什么是RAG系统呢？在实际项目中如何设计和优化RAG架构？
好的，RAG系统简单讲呢，就是检索增强生成，它本质上是把大模型和一个外部的知识库结合起来。因为大模型本身有个问题，它训练的数据是截止到某个时间点的，而且它容易一本正经地胡说八道，就是所谓的幻觉。那RAG的思路就是，在它回答之前，先从一个知识库里把相关的资料检索出来，喂给它做参考，让它基于这些真实材料去生成答案，而不是靠它自己的记忆瞎编。所以你看，它最核心的价值就是提升回答的准确性、可溯源性，还能做到知识实时更新，不用重新训练模型。
那如果让我在实际项目里去设计一套RAG架构，我会重点看三个环节。
第一个，向量数据库的选型。知识库里的文档要先用embedding模型转成向量存起来。选型的时候我一般考虑几件事：数据规模、查询性能还有成本。快速验证的阶段呢，用FAISS就够了，它轻量免费。不过它严格说是个检索库，本身不负责持久化数据，得自己存自己管。等数据量到了千万级甚至上亿，要分布式、要持久化，还要做过滤，那我会倾向用Milvus或者Weaviate这类专门的向量数据库。这里有个点就是，别一上来就上重的方案，够用就好。
第二个，检索策略。这个其实才是RAG效果好坏的关键，对大多数知识问答场景来说比选模型还重要。纯向量检索有时候会漏，尤其是那些专有名词、精确的关键词，所以我一般会做混合检索，就是把向量检索和关键词检索各自召回一批，再用RRF这种算法把两个结果集融合重新排序。如果用户问题本身很模糊，我还会加一层RAG-Fusion，就是让模型把问题改写成几个不同的query分别去查，然后合并去重，这样召回会更全。
第三个，知识的更新机制。这块很多人会忽略，但知识库是会过期的。我会分两种，一种是定时全量同步，比如每天晚上跑个批处理，把最新的文档重新切片、重新向量化；另一种是增量更新，数据源那边一有变化就通过消息队列触发，只更新变了的那几条，这样既保证新鲜度又省资源。
其实切块的粒度、要不要加rerank重排，还有怎么评估检索效果，这几块也都得管。总的来说吧，我认为RAG不是一个单点技术，它是一个系统，选型、检索、更新，每一块都得设计到位，最后的效果才真正靠谱
