# 记忆压缩——完整面试回答

---

## 开场：定位问题

面试官问"记忆压缩怎么做"，我会先说清楚**为什么这个问题在生产环境里真的很危险**，而不是直接上方案。

> "记忆压缩不是一个纯技术问题，它本质上是一个**业务风险问题**。我在医疗场景里见过最典型的例子：用户在第一轮告诉系统他对青霉素过敏，经过几十轮对话之后，如果压缩方案把早期内容丢掉了，系统可能在后续建议里开了含青霉素的药。这不是体验变差，这是安全事故。

---

## 第一部分：主流方案和疼点

> "目前生产环境里最常见的有两种：

> 第一种是**滑动窗口截断**，直接丢掉最老的消息，只保留最近 N 轮。实现零成本，LangChain 默认就是这个。但问题是它不管内容重不重要，一律按时间丢弃，早期的硬性约束、用户偏好、关键决策，全部悄悄消失，用户完全不知道。

> 第二种是**LLM 一次性摘要**，上下文满了之后，把整段历史发给模型生成摘要，再用摘要替换原文继续对话。细节保留比截断强，但有两个问题：第一，用户要等待，摘要生成需要时间，体验上有明显卡顿；第二，这是一次性全量压缩，越早期的内容越容易在摘要里被淡化，多压几次就是摘要的摘要的摘要，信息衰减是累积的。

> 这两种方案在医疗、法律、金融这类高风险场景里都是不够的。"

---

## 第二部分：我的方案


第一步，先做 Tool Result Masking，把旧的 tool result 替换为占位符，只保留最近5条完整结果。这一步不需要 LLM，零成本，立竿见影。

> **第一个机制：渐进式后台压缩。**

> 核心思路是把压缩成本从'触发时一次性支付'变成'每轮摊销'。不等到上下文满了再处理，而是每轮对话结束后，异步在后台做增量更新。但不是每轮都无条件写入，有两个触发条件：新增 token 量超过阈值，或者工具调用次数达到一定次数，满足任一条件才触发。写入内容是一个结构化的 summary，包含：当前工作状态、用户意图、关键决策、涉及的文件和函数、错误与纠正、硬性约束。

> 这个 summary 持久化写入 PostgreSQL，同时同步一份到 Redis 热缓存。当上下文真正需要压缩时，不需要临时调用 LLM 生成摘要，直接把预写好的 summary 加上边界之后的原始消息重新组装，基本上是瞬间完成。后续只需要增量更新 summary，不需要全量重算。

> **第二个机制：分层索引 + 懒加载。**

> 对于需要完整回溯的场景，比如法律合同审核、医疗复诊记录，不能接受任何细节丢失。我的做法是：完整保留最开始的 N 轮（包含用户的初始约束和背景）和最近的 N 轮（当前工作状态），中间的历史不丢弃，而是建一个结构化索引文件，记录每段对话的主题、关键词、涉及实体、存储路径。索引文件本身很小，插在中间的上下文里。当 LLM 判断需要某段历史的完整内容时，根据路径按需拉取，不需要的就不加载进上下文。"

---

## 第三部分：代价是什么

> "这套方案的代价我很清楚，主要有三个：

> 第一，工程复杂度显著上升。后台写入需要异步队列（比如 Celery 或 BullMQ），Redis 缓存需要维护缓存失效策略，数据库 schema 需要专门设计，成本会更高。

> 第二，网络延迟稀释了'瞬间压缩'的优势。本地文件读写几乎是零延迟，但写 PostgreSQL 有网络往返，读 Redis 也需要 1-2ms。这不是大问题，但需要缓存设计来补偿。

> 第三，在医疗这类受监管场景，summary 里可能包含患者信息，写进数据库就产生了合规义务，需要字段加密、访问审计，HIPAA 或 GDPR 的合规成本要单独算进去。

> 所以如果是小团队或者 MVP 阶段，我会建议先只做 Tool Result Masking，就是把旧的工具调用结果替换成占位符，只保留最近几条完整结果。JetBrains 的研究数据显示，这一步单独就能降低 50% 以上的 token 消耗，解决率有时还比 LLM 摘要更高，成本极低，是最高性价比的起点。渐进式压缩是在业务规模上来、细节丢失开始产生实际损失之后再引入的。"

---

 
## 结尾：一句话收

> "总结一下我的判断框架：滑动截断适合不在乎细节的场景；LLM 摘要适合中等复杂度的通用场景；渐进式压缩加分层索引适合高风险、需要完整回溯的场景。选方案之前先问一个问题：**如果某条信息被压缩丢失，最坏的结果是什么**。如果答案是用户体验变差，可以接受简单方案；如果答案是安全事故或法律责任，就必须上双轨机制。"

## 面试官可能的追问和你的答案

| 追问 | 答法 |
|------|------|
| Redis 挂了怎么办？ | 降级读 PG，加一层 try/except，慢但不崩 |
| summary 写入失败怎么办？ | 熔断器，连续失败3次停止重试，fallback 到全量 LLM 摘要 |
| 怎么判断哪些信息是硬性约束？ | 单独跑一个分类 sideQuery，专门提取约束类信息，写入独立存储 |
| 这套方案成本比纯 LLM 摘要贵多少？ | 后台写入是增量小模型调用，摊销后单轮成本极低，贵的是工程成本不是 API 成本 |
| 小公司用不用得起？ | 先只做 Tool Result Masking，够用了再加；渐进式压缩是规模化之后的事 |
