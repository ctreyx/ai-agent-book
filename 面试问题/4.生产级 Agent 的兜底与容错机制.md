# 第六题满分回答：生产级 Agent 容错机制

---

> **生产级 Agent 和 Demo 级 Agent 最大的区别不是功能，而是出了问题能不能自己兜住。我从四个维度系统说一下。**
>
> ---
>
> ### 一、Token 控制
>
> **第一，任务入口设 Token 预算上限。** 每个任务进来之前，先估算这次任务的复杂度，分配一个 Token 上限——比如简单问答 2K、RAG 检索 8K、复杂规划 20K。超预算直接截断终止，不等熔断才停。这样 Token 消耗在入口就有了上界。
>
> **第二，按环节选模型。** 不是所有环节都需要顶级模型。越权判断、意图分类这种简单决策用轻量级小模型，只有生成最终答案才用大模型。这是成本控制最直接的手段。
>
> **第三，Prompt 压缩而非全量传入。** 工具返回的结果可能很长，不需要全部塞进下一轮 Prompt。提取关键字段、压缩冗余内容，只传模型决策需要的最小信息集。
>
> **第四，熔断 + 降级。** 这是最后一道防线——循环次数上限、重复工具调用检测，触发后立即终止，降级为友好提示，不让 Token 无限消耗。
>
> ---
>
> ### 二、延迟控制
>
> **第一，异步后台执行非关键任务。** 比如记忆提取、记忆整合、日志上报这些任务，不应该阻塞主对话。Claude Code 的长期记忆召回就是通过 prefetch 放在后台执行的——用户发消息的同时后台已经在准备上下文了，不产生额外等待。
>
> **第二，任务并行。** 独立的子任务并行执行。比如同时查天气和查景点信息，延迟从串行的 A+B 变成 max(A,B)，在多工具场景下收益非常显著。
>
> **第三，渐进式摘要维护上下文。** 后台持续维护一个 summary，上下文接近窗口上限时，直接把中间部分替换为这个 summary，而不是临时调 LLM 做摘要再等结果。好处是没有中间等待，而且 summary 是实时维护的，细节保留更完整。
>
> **第四，流式输出。** 首 Token 出来就推给用户，不等完整结果生成再返回。对于用户感知来说，从"等 10 秒看到结果"变成"1 秒内开始看到内容"，体验提升是质的飞跃。同时设置首 Token 超时——超过 N 秒没有首 Token 返回，直接触发降级。
>
> ---
>
> ### 三、异常处理
>
> **第一，分级重试策略。** 工具调用失败不是直接报错，而是先重试。重试策略用指数退避——第一次等 1 秒、第二次 2 秒、第三次 4 秒，最多重试 3 次。同时区分可重试错误（网络超时、服务暂时不可用）和不可重试错误（参数错误、权限不足），后者直接跳过重试走降级。
>
> **第二，Checkpoint 恢复。** Agent 执行过程中，每个关键节点完成后保存一次 checkpoint——记录当前 State、已完成的工具调用结果、当前进度。某个节点失败时，从最近的正确 checkpoint 继续执行，不需要整个任务重跑。这是 LangGraph checkpoint 机制的核心思路。
>
> **第三，记忆回滚。** 记忆系统本身也可能出 bug——压缩后内容丢失、文件损坏。所以每次记忆更新前要保存快照，更新失败时回滚到上一个版本。Claude Code 的 autoDream 就是可逆设计，出问题直接 diff 回滚。
>
> **第四，全链路异常捕获 + bad case 上报。** 所有被熔断、重试失败、异常终止的 case，自动上报到监控系统，同时存入 bad case 库。运维能实时看到异常，开发能定期从 bad case 里提取 Prompt 优化方向，形成线上反馈闭环。
>
> ---
>
> ### 四、用户体验
>
> **第一，过程透明。** 这是 Agent 和传统接口最大的体验差异。不能让用户对着转圈等 30 秒不知道发生了什么。每个关键节点实时推送进度——"正在检索景点信息..."、"正在查询天气..."、"正在规划路线..."。用户知道系统在工作，等待感大幅降低。
>
> **第二，优雅降级而不是报错崩溃。** 某个工具调用失败、某个环节超时，不能让整个对话崩掉。要有兜底答案——"我目前无法查询实时价格，以下是我知识库里的参考信息"。用户感知到的是"有限帮助"而不是"系统出错"。
>
> **第三，长期记忆让用户感到被记住。** 用户上次说"我不吃辣、偏好步行景点"，这次对话开始时自动带入这些偏好，不需要重复说。这是 Agent 区别于普通搜索最核心的体验价值。
>
> **第四，高风险操作前要确认。** 涉及支付、数据修改、权限操作，Agent 不能自己偷偷做。必须先展示计划、等用户确认再执行。这不只是用户体验问题，也是安全问题。
>
> ---
>
> ### 五、一句话总结
>
> **生产级 Agent 的容错体系本质上是四道防线：入口控制成本、过程控制延迟、异常保证可恢复、用户体验保证可信任。每个环节都会失败概率，所以我们最初设计的适合就需要为每个失败预设代价上界和恢复路径。**
