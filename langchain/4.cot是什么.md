# 🎯 面试场景：什么是 CoT（思维链）？

---

## 💬 这样回答（一句话版）

CoT 全称 Chain of Thought（思维链），是 2022 年 Google Brain 提出的提示工程技术，也是 Agent 推理能力的基础范式。

简单说：普通 Prompt 是让模型直接输出答案；CoT 是强制模型先输出中间推理步骤，再给出最终结论，模拟人类"拆解问题 → 逐步推导 → 校验 → 得出答案"的思考过程。

它本质是提示词层面的优化，不需要改动模型权重，所有主流大模型都可以通过 Prompt 触发。

---

## ⚠️ 高频考点：CoT 和 ReAct 的区别

这是面试里最容易被追问的点，一句话区分：

| 对比维度 | CoT | ReAct |
|---|---|---|
| 工作方式 | 只在内部思考 | 一边思考一边行动 |
| 推理形式 | 纯文本推理 | Thought → Action → Observation 闭环 |
| 工具调用 | 不调用外部工具 | 调用外部工具/环境交互 |
| 适用场景 | 数学题、逻辑推导、纯文本分析 | Agent 实时决策、执行真实任务 |
| 缺点 | 无法获取实时信息，易知识幻觉 | 更复杂、成本更高 |

一句话：**CoT 是"只想不做"，ReAct 是"边想边做"。** ReAct 是 CoT 的延伸。

---

## 总览对比

| 名称 | 全称 | 核心做法 | 难度/成本 | 典型场景 |
|---|---|---|---|---|
| Zero-shot CoT | 零样本思维链 | 只加一句提示词 | 最低 | 快速提升复杂题正确率 |
| Few-shot CoT | 少样本思维链 | 给几个带完整推理的例子 | 中 | 需要稳定格式、特定领域 |
| Auto-CoT | 自动思维链 | 自动聚类 + 自动生成示例 | 中高 | 不想人工写大量 few-shot |
| ToT | 思维树 | 多路径探索 + 评估 + 剪枝 | 最高 | 很难的规划/搜索类问题 |

**它们解决的都是：别让模型直接蹦答案，而是把"思考过程"用起来。**

---

## 1. Zero-shot CoT（零样本思维链）

**是什么**：不给任何例子，只在提示词末尾加一句固定话术，强制模型一步步想。

经典句式：

```text
英文：Let's think step by step.
中文：请一步步思考。/ 让我们一步一步分析。
```

**例子**：

```text
Q: 商店里苹果 3 元一个，买 4 个打 8 折，小明带了 20 元够不够？
A: Let's think step by step.
```

模型会自己写出：

> 原价 3×4=12 元 → 打 8 折 12×0.8=9.6 元 → 20>9.6 → 够。

**特点**：

- 几乎零成本，改一行 prompt 就行
- 对算术、常识推理提升明显（原论文在某些任务上提升很大）
- 缺点：格式不可控、复杂领域不稳定、没有"示范"时容易跑偏

**一句话**："不教，只喊一声：慢慢想。"

---

## 2. Few-shot CoT（少样本思维链）

**是什么**：在 prompt 里放 2～8 个完整示例，每个示例都是：问题 → 一步步推理 → 最终答案。模型会模仿这种格式和推理风格。

**例子（示意）**：

```text
Q: 罗杰有 5 个网球，又买了 2 罐，每罐 3 个，现在共有几个？
A: 罗杰原来有 5 个。2 罐×3 个=6 个。总共 5+6=11 个。答案是 11。

Q: 食堂有 23 个苹果，用了 20 个做午饭，又买了 6 个，现在有几个？
A: 23-20=3，3+6=9。答案是 9。

Q: 【用户真正的问题】
A:
```

**特点**：

- 比 Zero-shot 更稳、格式更好控制（方便后面用正则/解析器抽 Action）
- 适合 Agent：你可以示范 Thought → Action → Observation 的写法
- 缺点：
  - 要人工精心挑选/编写例子
  - 例子占 token，贵
  - 例子选得差会误导模型（分布不匹配）

**一句话**："先做几道带详细步骤的例题，再让模型照着做。"

---

## 3. Auto-CoT（自动思维链）

**是什么**：解决 Few-shot 的痛点——人工写例子又贵又容易偏。

流程大致是：

```text
1. 从题库里自动采样大量问题
2. 用向量聚类（相似问题分到一类）
3. 每一类里抽代表问题，用 Zero-shot CoT 让模型自动生成推理链
4. 过滤掉明显错的推理
5. 把这些自动生成的「问题+推理」当作 Few-shot 示例
→ 得到自动构建的 Few-shot CoT prompt
```

**特点**：

- 减少人工标注
- 例子覆盖更广、更有代表性
- 仍依赖：聚类质量、错误推理过滤、额外的前置生成成本
- 工程上比手写 few-shot 重一档

**一句话**："用聚类 + Zero-shot，自动批量生产 Few-shot 例题。"

---

## 4. ToT（Tree of Thoughts，思维树）

**是什么**：

- CoT 是一条链（一条推理路径到底）
- ToT 是一棵树：同一问题探索多条思路，像搜索算法一样

**核心步骤**：

```text
1. Thought 生成：每一步提出多个候选"下一步想法"（分支）
2. 评估/投票：对每个候选打分（自己评、另一个 LLM 评、或规则评）
3. 搜索策略：BFS / DFS / beam search，保留好的分支，剪掉差的
4. 回溯：某条路走不通就退回换一条
5. 最终从整棵树里选出最优路径 → 答案
```

**和 CoT 的直观对比**：

```text
CoT（链）:
  想法1 → 想法2 → 想法3 → 答案
  （一条路走到黑，错了就全错）

ToT（树）:
        想法A
       /     \
    想法B    想法C
    /  \       \
  ...  ...     答案（选最优）
```

**典型适用**：

- 创意写作多方案比较
- 谜题、规划、多步博弈
- 需要"试错 + 回溯"的任务
- 24 点、积木规划等经典实验任务

**特点**：

- 推理上限通常高于单链 CoT
- 代价极高：多次 LLM 调用（生成分支 + 评估），延迟和 token 都贵
- 工程复杂：要维护树状态、搜索策略、剪枝阈值
- 和 Agent 结合时很像：多计划并行、工具试错、再选最优

**一句话**："不要一条道走到黑，像搜索树一样多想几条路，评估后再走。"

## 关系图（从弱到强）

```text
Zero-shot CoT     只加一句 "step by step"
      ↓
Few-shot CoT      人工给带推理的例子
      ↓
Auto-CoT          自动生成那些例子
      ↓
ToT               从"一条链"升级成"多路搜索树"
```

---

## 相关变体（面试可能听到）

| 变体 | 说明 |
|---|---|
| Self-Consistency | 同一题用 CoT 采很多条路径，最后投票 |
| GoT（Graph of Thoughts） | 比树更一般的图结构推理 |
| ReAct | CoT（Thought）+ 工具调用（Action），Agent 里极常用 |

---

## 和 AI Agent 的对应关系（面试加分）

| 技术 | 在 Agent 里怎么用 |
|---|---|
| Zero-shot CoT | 节点 prompt 里加"先思考再决策" |
| Few-shot CoT | 示范 Thought/Action 格式，稳定解析 |
| Auto-CoT | 离线构建领域示例库，注入 Agent prompt |
| ToT | 复杂规划：多方案并行评估再执行（贵，慎用） |

你之前做的 HyDE、失败带原因重试、Self-RAG 打分，更接近：**单路径 CoT + 外部校验**，而不是完整 ToT。

可以说：

> 我们用的是条件触发的单链推理 + 校验回环；ToT 这种多路搜索成本太高，只在极少数高价值决策节点才考虑。

---

## 🎯 30 秒面试口述版

> Zero-shot CoT 就是提示词里加一句"一步步思考"，不给例子。
> Few-shot CoT 是给几个带完整推理步骤的示例，让模型模仿。
> Auto-CoT 用聚类和自动生成，减少人工写 few-shot 的成本。
> ToT 把一条思维链升级成树状多路径搜索，能探索、评估、剪枝，效果更强但调用次数和成本高很多。
> Agent 里最常用的是 CoT 思想结合工具调用，也就是 ReAct；ToT 更适合特别难的规划问题。
