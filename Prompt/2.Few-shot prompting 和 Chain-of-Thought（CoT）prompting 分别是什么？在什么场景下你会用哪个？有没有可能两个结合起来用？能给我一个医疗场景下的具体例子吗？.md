# Few-shot prompting 和 Chain-of-Thought（CoT）prompting 分别是什么？在什么场景下你会用哪个？有没有可能两个结合起来用？能给我一个医疗场景下的具体例子吗？

1) Few-shot prompting 是什么？
Few-shot prompting（少样本提示）：在你真正要模型完成任务之前，先在 prompt 里给它 少量“输入→输出”的示范样例（通常 2–5 个），让模型“照着例子学会你要的格式/风格/决策边界/标签体系”。它属于 in-context learning（上下文学习）：不改模型参数，不训练，只靠你放进 prompt 的例子来临时对齐行为。 
1

本质作用：

把你脑子里的“隐性标准”（比如：什么算高危、输出要几段、用什么术语、要不要引用证据、要不要给免责声明）变成模型可模仿的“显性样例”。 
2
典型特征：

更擅长 “对齐输出形状”：格式、语气、分类标签、模板化结构、边界条件。
对复杂推理本身不一定最强，但能显著减少“跑题/风格飘/分类标准不一致”。
2) Chain-of-Thought（CoT）prompting 是什么？
CoT prompting（思维链提示）：通过提示让模型在回答前（或回答中）进行多步推理，把问题拆成步骤来做，从而提升复杂任务（数学、逻辑、多跳推断、规则推理等）的正确率。经典论文表明：给出带推理步骤的示例（或要求逐步推理）能显著提升多步推理表现。 
3

OpenAI 的文档也提到：让模型“step by step（链式思考）”常能提升质量，但代价是输出 token 增加、延迟和成本上升。 
4

本质作用：

更像是在帮模型“把脑内计算写出来”，让它不要一口气拍答案，而是按步骤检查。
适合需要推理正确性而不是只要“像”。
实务上还有一条重要经验：CoT 常会被进一步搭配“多样采样 + 投票”的 self-consistency（自一致性） 来提高准确率：同一题采样多条推理路径，最后用多数答案。 
5

3) 在什么场景用哪个？（决策表）
目标/场景	更优先用 Few-shot	更优先用 CoT
你要模型严格按模板输出（病历摘要结构、SOAP、鉴别诊断表格、风险分层等级等）	是：用例子“钉死格式”和标签口径	不一定需要
你要模型学会你的偏好/风格（更谨慎、更短、更像临床记录/更像给患者解释）	是：示例最有效	可选
你要模型做多步推理（根据症状→风险分层→下一步检查→红旗提示→处置建议）	可能辅助（用示例告诉它怎么组织推理产物）	是：核心手段
你担心模型“想当然”、需要它显式检查矛盾/缺失信息	有帮助（示例展示如何指出缺口）	是：逐步核对更有利
你在意成本/延迟	相对便宜（少量示例即可）	通常更贵（更多输出 token） 
4
一句话策略：

输出规范优先 → few-shot
推理正确优先 → CoT
既要规范又要正确 → two-in-one：few-shot + CoT（很常见）

### 概念补充

**Few-shot Prompting：**
- 不只是"举例"，本质是**通过示例让模型学会输入→输出的映射模式**，不需要训练
- Zero-shot = 不给例子，Few-shot = 给 2~5 个例子

**Chain-of-Thought (CoT)：**
- 不只是"拆分任务"，核心是**让模型把推理过程显式地写出来**，而不是直接跳到答案
- 为什么有效？LLM 是自回归的，前面生成的 token 会影响后面——把中间步骤写出来，相当于给自己"打草稿"，降低推理跳步出错的概率

### 面试官想听到的具体例子

**Few-shot 医疗示例：**

```
你是一个医疗分诊助手，请判断患者症状的紧急程度。

示例1：
患者：我胸口剧烈疼痛，出冷汗
判断：🔴 紧急 - 疑似心梗，立即就医

示例2：
患者：最近嗓子有点痒，偶尔咳嗽
判断：🟢 普通 - 疑似轻微上呼吸道感染，可先观察

现在请判断：
患者：我头疼了三天，吃了布洛芬没用
```

**CoT 医疗示例：**

```
请一步步分析这个患者的情况：

患者描述：女，45岁，反复头痛3天，伴恶心

请按以下步骤推理：
1. 关键症状提取：...
2. 可能的诊断方向：...
3. 需要排除的危险情况：...
4. 建议：...
```

**两者结合（Few-shot CoT）：**

```
示例：
患者：男，60岁，胸闷气短一周
分析过程：
1. 关键症状：胸闷、气短、老年男性
2. 可能方向：心血管疾病（冠心病、心衰）、呼吸系统（COPD）
3. 危险排除：需排除急性心梗、肺栓塞
4. 建议：建议尽快心内科就诊，做心电图+胸片

现在请用同样的方式分析：
患者：女，35岁，持续腹痛两天，伴低烧
```

> 这就是 Few-shot + CoT 结合——**用示例教会模型"推理的格式和深度"**，比单独用任何一个效果都好。

> 💡 面试建议：Prompt 类问题，**一定要给出可以直接跑的 prompt 示例**，不要只说概念。面试官脑子里会想"你真的写过吗"，一个具体例子就能打消他的疑虑。
